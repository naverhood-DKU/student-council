# Worker 동시 실행과 작업 인계

## 구현 및 로컬 검증 (2026-10-12)

- 공유 CLOVA 예산 행의 `INSERT IGNORE` 초기화와 `FOR UPDATE` 예약은 별도 짧은 트랜잭션으로 실행한다. 초기화의 공유 잠금을 예약의 배타 잠금으로 올리면서 발생한 실제 MySQL deadlock을 재현했다.
- deadlock/lock wait 실패는 새 트랜잭션으로 최대 3번 시도한다. 예산 예약 커밋 전 AI를 호출하지 않는다. HTTP 호출·대기는 DB 트랜잭션 밖에서 실행한다.
- 작업 임대 90초, 독립 심박 15초. AI 요청과 quota 대기 중에도 갱신한다. 갱신 조건은 작업 ID·RUNNING·소유권 version·미만료 임대다. 심박은 소유권 version을 변경하지 않는다.
- DB UTC 시각으로 심박을 갱신한다. 서버는 시간 동기화를 유지한다. 호출 예산 안내는 임대를 갱신하지 않는다.
- 심박 실패/소유권 상실 시 실행 스레드를 중단하고 결과를 버린다. 최종 결과/실패 저장은 행 잠금 후 version·상태·만료를 확인한다. 외부 AI 호출은 exactly-once를 보장하지 않으며, 재처리에 의한 API 재소비는 가능하다.
- 실제 MySQL: 기존 행/빈 행/시간창 전환/냉각·피드백 경합 각각 100회. 짧게 설정한 임대보다 오래 걸리는 AI 응답, 소유권 상실 후 인계, 만료 임대 부활 방지, 심박 DB 실패를 검증했다. 전체 백엔드 100개, 프론트 5개 테스트 및 빌드 통과.

## 배포 및 운영 검증 대기

위 테스트 통과가 두 Worker 운영 검증을 대신하지 않는다. PR CI → 단일 Worker canary → 동일 jar의 KR-2 임시 Worker 순으로 적용한다. 50건×3회씩 비교와 양쪽 장애 인계를 통과한 뒤 최종 Worker 수를 결정한다. 원출력·서버 ID/IP·캡처는 로컬에만 보관한다.
