# CLOVA 호출량 제어와 대기 안내 구현 계획

사용자가 승인한 흐름: 요청은 정상 접수하고 호출 한도 때문에 실패시키지 않는다. 처리 가능한 시점까지 기다리며 화면에 대기 안내를 표시한다. 배포 후 동일한 합성 회의록 50건으로 다시 검증하고 로컬 보고서에 기록한다.

## 설계

- 실측 한도는 HCX-007 QPM 60, TPM 60,000이다. 10% 여유를 둔 54회·54,000토큰을 초기 로컬 예산으로 사용한다. 같은 메인 계정·모델·이용 목적의 Worker는 동일 scope를 사용한다.
- MySQL의 공유 예산 행을 짧게 잠가 예약한다. 외부 HTTP 호출이나 대기 중에는 DB 트랜잭션을 유지하지 않는다. 재시작 후에도 창과 냉각 시각이 유지된다.
- 공식 v3 토큰 계산기로 입력 메시지와 응답 스키마를 계산하고, 최대 출력 8,192 및 작은 보정 여유를 합산한다. 길이에 따른 처리 비용을 제어한다.
- 429의 공급자 reset/Retry-After를 반영한 냉각을 공유한다. 같은 호출의 대기는 일반 실패 3회 예산을 소모하지 않는다. 공급자 처리 여부가 불명확한 타임아웃은 기존 정책대로 FAILED_UNKNOWN이다.
- 긴 회의록의 중간 결과는 현재 실행 안에서 유지한다. 호출 대기 중 작업 임대를 주기적으로 갱신하고 소유권을 확인한다. RUNNING에 quotaWaitUntil을 노출한다. QUEUED는 접수·순서 대기, 실제 호출 제한 대기는 별도 안내한다.
- 무한 대기는 피하도록 호출별 대기 한도를 설정하고 명확한 실패 코드로 구분한다. 모델에 없는 내용이나 사용자 원문을 로그에 남기지 않는다.

## 실행

- [x] 공유 예산의 요청·토큰 고갈, 시간 경과 재개, 두 실행자의 동시 예약, 재시작 및 429 냉각을 테스트 우선으로 구현한다.
- [x] 실제 클라이언트의 토큰 계산·429 재개·타임아웃 구분과 작업 임대 보호를 테스트한다.
- [x] 대기 안내 문구와 상태 구분을 구현하고 프런트 테스트 및 빌드를 실행한다.
- [x] ./mvnw verify를 통과하고 변경 범위를 검토한다. 작은 커밋·기존 브랜치 PR로 기록한다.
- [x] Worker와 App를 배포하고 ASG 이미지도 새 버전으로 갱신한다.
- [x] 새 로컬 증거 폴더에 50건 실험·상태 화면·최종 정상 상태를 저장한다. 이전 실패 결과는 보존하고 보고서에 후속 검증을 추가한다.

외부 API 참고: https://guide.ncloud-docs.com/docs/clovastudio-ratelimiting , https://api.ncloud-docs.com/docs/clovastudio-tokenizerhcxv3

## 검증 완료

백엔드 전체 테스트 93개와 프런트 테스트 5개, JDK 21의 ./mvnw verify가 통과했다. 실제 배포와 새 ASG 이미지 부팅을 확인하고 기본 App 2대로 복원했다. 재시험 원출력·캡처·개선 전후 보고서는 사용자 요청대로 로컬에만 보관한다.
