# 운영 사양·비용 결정 — 2026-10-10

예산 2,250,000원, 발표 마감 2026-10-16. 아래는 실제 배포한 초기 구성이다. 단국대 전체 학생자치 조직 확대를 고려하지만 동시 사용자 수와 분석 처리량은 아직 측정하지 않았다. App 2~4대는 초기 실험 범위이며 검증된 용량 보장치가 아니다.

| 역할 | 초기 수 | 실제 사양·배치 | 이유 |
| --- | --- | --- | --- |
| App | 2 | KR-1·KR-2 각 s2-g3 2vCPU·8GB, CB1 10GB | 한 App 장애 시 남은 App 처리; 각 존 ASG min1/max2 |
| Worker | 1 | KR-1 s2-g3 2vCPU·8GB, CB1 10GB | AI 대기·재시도를 웹 요청과 분리 |
| Bastion | 1 | KR-1 c2-g3 2vCPU·4GB, CB1 10GB | 관리 IP /32에서만 공개키 SSH |
| MySQL HA | 2 | KR-1 Master·KR-2 Standby, G3 AMD 각 2vCPU·8GB, CB2 데이터 10GB | 자동 장애 전환 구성; 읽기 분산용 아님 |
| Application LB | 1 | PUBLIC SMALL, 두 존 연결, HTTP 80 | 데모 요청 분산; HTTPS는 도메인 확보 후 |
| NAT | 2 | 존별 1개 | Private 서버 외부 API·설치 통신 |
| 이미지 준비 서버 | 중지 1 | KR-1 s2-g3, CB1 10GB 유지 | 서버 실행 비용 중단; 디스크 비용 유지 |

G2 생성 한도는 0대여서 G3로 전환했다. provider 4.0.5가 G3 실행 템플릿 필드를 지원하지 않아 공식 API로 부팅 스냅샷·이미지·Launch Configuration을 생성하고 번호를 Terraform에 전달했다. 두 존의 새 ASG App 기동과 LB 건강 응답을 확인했다. 별도 API 자원은 삭제 때도 별도 확인해야 한다.

## 비용 계획

정확한 최종 견적은 NCP 콘솔 사용 내역과 대조한다. 기존 G2 견적은 현재 배포의 견적이 아니므로 폐기했다. 아래 고정 단가 외에 MySQL G3 사양·CB2·백업·이미지/스냅샷·Object Storage·데이터 전송·AI 사용량을 추가해야 한다.

| 확인한 항목 | 시간 단가(부가세 별도) |
| --- | --- |
| s2-g3 CPU/메모리 | 115원 × 실행 3대 |
| c2-g3 CPU/메모리 | 92원 × 1대 |
| CB1 10GB | 1.6원 × 5대(중지 이미지 서버 포함) |
| NAT | 56원 × 2개 + 처리량 |
| Application LB SMALL | 26원 + 데이터/규칙 |
| 공인 IP | 5.6원 × 3개(Bastion 1, LB 2) |

위 부분만 합하면 시간당 599.8원, 7일 168시간 부가세 포함 약 11.1만 원이며 **전체 비용이 아니다**. DB·AI 등을 포함한 최종 금액은 사양별 콘솔 요금 확인과 일별 사용 내역으로 갱신한다. App을 2대 추가해 7일 내내 유지하면 CPU/메모리·CB1 기준 약 4.3만 원이 추가된다. Worker 추가도 같은 단가이며 현재는 추가하지 않았다. 같은 App 수를 두 존에 분산하는 것 자체는 서버 비용을 늘리지 않지만 이 구성의 NAT 추가 1개는 7일 약 1.03만 원이다.

## 검증 시나리오

- 조회 트래픽: 로그인·업무보드·회의록 조회를 늘려 오류율·p95·처리량·DB 연결 수 비교.
- 동시 회의 분석: 여러 조직의 작업을 동시에 넣어 대기 시간·성공률·AI 호출 제한·처리 시간을 비교. App 수만 늘리면 AI 처리량이 늘어난다고 주장하지 않는다.
- App 장애: App 서비스를 중지하고 남은 App 응답·LB 제외·ASG 대체 서버 정상화 시간을 관측. 존 전체 재해 복구 시험과 구분한다.
- Worker 장애: 현재 1대라 복구 전 작업이 지연된다. 임대는 10분이며 갱신 PR #2가 아직 배포되지 않았다. 긴 작업·중복 실행·재시도는 해당 변경 후 검증한다.
- DB 장애 전환: HA 구성만 완료했고 실제 전환 시험은 후속 과제다. 연결 풀 재연결을 측정한다.

Bastion 1대는 관리 경로의 단일 장애점이며 서비스 요청 경로 밖이다. CPU 정책은 >80% 3분 증설/<30% 10분 축소라는 초안이고 총 App 상한 4대도 검증 후 조정한다. HTTPS와 DB 통신 암호화가 아직 없으므로 가상 데이터 데모만 허용한다. 로컬 Terraform state는 강대운 1명만 실행하며 협업 전에 원격 상태·잠금·복구를 마련한다. 발표 후 유지/삭제 결정일을 기록하고 자원별 잔여 과금을 확인한다.
