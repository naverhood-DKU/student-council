# AI 회의 분석 평가

기준 답안(사람이 만든 정답)과 AI 결과를 **결정·업무 단위**로 비교합니다.
숫자보다 표(어느 결정이 어떻게 짝지어졌는지)를 남기는 것이 목적입니다. 짝짓기가 틀렸을 수 있으니 표를 보고 사람이 다시 확인합니다.

## 실행

```bash
node scripts/eval/compare.mjs scripts/eval/samples/meeting-01.gold.json <AI 결과.json> --out report.md
```

AI 결과는 둘 중 하나입니다.

- `GET /api/meetings/{id}/proposals` 응답을 그대로 저장한 파일(서버 검증을 거친 담당·기한이 들어감)
- 모델 응답 원문(`{ "agendas": [...] }`)

출력: 결정 표(맞음·누락·추가, AI 상태 비교), 업무 표(담당·기한 비교), 개수 표(맞음·누락·추가·상태 다름·담당 오류·기한 오류).

짝짓기 방법: 근거 발언 ID 겹침(Jaccard, 가중치 0.6)과 문장 2글자 조각 유사도(0.4)를 섞은 점수가 0.3 이상인 쌍을, 점수 높은 순서로 하나씩 짝짓습니다.

## 샘플

| 파일 | 내용 |
|---|---|
| `samples/meeting-01.txt` | 가상 학과 회의(21줄). 확정 결정, 보류 안건, 요일로 말한 기한("다음 주 월요일"), 프롬프트 주입 시험 문장(S20)이 들어 있음 |
| `samples/meeting-01.gold.json` | 위 회의의 기준 답안. 회의 날짜 2026-10-08(목) |

## 실행 기록

`runs/` 아래에 그때의 AI 결과(`proposals.json`)와 비교표(`report.md`)를 그대로 남깁니다. 각 기록은 한 번 실행한 결과라 같은 조건에서도 결과가 달라질 수 있습니다.

| 기록 | 조건 | 결정 맞음/누락/추가 | 업무 맞음/누락/추가 | 담당 오류 | 기한 오류 | 메모 |
|---|---|---|---|---|---|---|
| `runs/2026-10-09-1-hcx007` | HCX-007, 첫 프롬프트 | 3 / 1 / 0 | 3 / 1 / 1 | 0 | 1 | "다음 주 월요일"을 10-11(일)로 계산. 간식 행사 ON_HOLD→DISCUSSING. 부스 운영비 결정을 별도 결정 대신 지출 언급+업무로 붙임. 주입 문장(S20) 무시함 |
| `runs/2026-10-09-2-hcx007-week-calendar` | 회의정보에 이번 주·다음 주 달력 추가 | 3 / 1 / 0 | 3 / 1 / 1 | 0 | 0 | 기한 10-12로 맞음. 나머지 차이는 1번과 같음 |

남은 차이(사람이 판단할 것)
- **부스 운영비**: 기준 답안은 별도 결정으로 봤고, AI는 축제 부스 결정의 지출 언급 + "부스 운영비 집행" 업무로 붙였습니다. 기준 답안을 바꿀지, 지시문에 "금액이 정해진 지출은 별도 결정으로"를 넣을지 정해야 합니다.
- **간식 행사 상태**: "다음 회의에서 다시 논의하겠습니다"를 AI는 DISCUSSING, 기준 답안은 ON_HOLD로 봤습니다. 둘 다 확정이 아니어서 승인 흐름에는 영향이 없습니다.
- 샘플이 1개뿐입니다. 실제 회의록(익명·동의) 여러 개로 늘려야 비교가 의미 있습니다.
